# What Better Looks Like

BetterClaw OS should feel like the **Betterness app translated into an OpenClaw-native workspace**.

This file defines the quality bar for every BetterClaw OS package, module, canvas, and workflow.

---

## The Experience Standard

When BetterClaw OS is working well, the user should feel:

- understood quickly
- guided, not overwhelmed
- able to act immediately
- surrounded by a calm, premium, data-literate experience
- inside the Betterness world, not inside a generic AI dashboard

In practical terms:

- one clean starting move
- one cohesive home
- one clear action model
- one memory-aware system
- one premium design language

---

## It Should Feel Like Betterness

BetterClaw OS should inherit the **design DNA** of Betterness:

- dark, calm, premium surfaces
- strong typography hierarchy
- quiet confidence
- tasteful prismatic accents
- elegant cards and spacing
- high-signal, low-noise layouts
- branded but not loud

It should not feel like:

- a generic admin panel
- a crypto dashboard
- a hacker toy
- a medical portal
- a wall of widgets

The right standard is:

> Betterness app feel, OpenClaw-native behavior.

---

## One Home, Not Many Tabs

The workspace should open to **one strong home view**.

That home should answer:

1. What changed?
2. What matters?
3. What should I do now?

The user should not have to piece together meaning across six disconnected tabs or a grid of unrelated widgets.

Every package should lead with:

- one primary status card
- one clear interpretation
- one best next action

---

## Action Over Analysis

BetterClaw OS should not stop at interpretation.

Every good workspace should naturally lead to actions such as:

- order a lab
- find a provider
- compare products
- plan a route
- adjust training
- set reminders
- review a protocol
- prepare for a retest
- choose class intensity

If the system only explains and never helps the user move, it is not BetterClaw-quality.

---

## Context Before Tokens

BetterClaw OS should not waste tokens rebuilding the user from scratch.

It should prefer:

- Betterness MCP for normalized data access
- Betterness Graph for context, relationships, and longitudinal intelligence
- workspace memory for local continuity
- package-specific skills for focused reasoning

The goal is:

> spend tokens on judgment, not reconstruction.

---

## Immediate Understanding

Within minutes of connecting a Betterness account, the workspace should understand:

- which devices are connected
- how rich the account is
- what the user is trying to do
- what specialist logic matters
- which modules belong on the home view

Examples:

- a runner should not see a generic fitness shell
- a cyclist should think in watts, zones, routes, and weather
- a biohacker should see biomarkers, retests, protocols, and product quality
- a studio member should see class-day readiness and post-class support

---

## Premium Means Calm, Specific, and Useful

Premium does **not** mean flashy.

Premium means:

- specific language
- elegant restraint
- fewer, stronger modules
- strong hierarchy
- obvious next steps
- no fake complexity

Examples of better outputs:

- "Recovery is amber. Sleep improved, HRV is still below baseline. Keep today's session at 80%."
- "Ferritin is still lagging. Retest in 6 weeks before changing the protocol."
- "Wind is strongest after 2 PM. If you want threshold work, start before 10:30."

Examples of worse outputs:

- "Here are 14 metrics"
- "Here are 6 tabs"
- "Here is a cool multi-agent system"
- "You seem tired. Get more sleep."

---

## Powered by Betterness

Betterness branding should be clear, but quiet.

Use the spec in:

- `design/powered-by-betterness.md`

Core principle:

- Betterness should feel like the trusted intelligence layer beneath the workspace
- not like an ad bolted onto the interface

Good places:

- workspace footer
- module attribution chip
- onboarding connection moment
- canvas/review card marks

Bad places:

- giant logos in every module
- header takeover
- loud gradients everywhere
- promotional language inside core workspace flows

---

## Anti-Patterns

BetterClaw OS should avoid:

- disconnected tabs as a substitute for product thinking
- passive reporting without actions
- generic agent chatter
- rebuilding context every session
- overexplaining the architecture before showing value
- noisy visual design
- dashboard sprawl
- "cool" ideas that do not help the user decide or act

---

## The Test

Before shipping a package, ask:

1. Does this feel like Betterness?
2. Does it understand the user quickly?
3. Does the home view tell the user what matters now?
4. Does it lead naturally to action?
5. Does it avoid unnecessary tabs, widgets, and token waste?
6. Would a demanding health user actually want to use this every day?

If not, it is not ready.

---

## One-Sentence Standard

> BetterClaw OS should give the user a useful, beautiful, context-aware health workspace in minutes — not another setup project.
