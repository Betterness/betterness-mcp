# Community Contribution Path

Use this file when you want the Betterness mission-control starter to become something other builders can actually reuse.

## Good contributions

- new persona overlays with a clear health workflow
- stronger prompt packs grounded in real Betterness tools
- mission-control panels that improve operator visibility
- install docs that reduce setup failure
- playbook adaptations for a real vertical

## What every contribution should include

1. What this asset is
2. Who it is for
3. What problem it solves
4. Which Betterness tools or helper surfaces it expects
5. A smoke test
6. A limitation or guardrail section

## Quality bar

- use real Betterness capabilities
- do not imply autonomous medical care
- keep external context clearly separated from Betterness-native execution
- prefer small reusable modules over giant monolithic rewrites

## What gets featured and supported

The strongest public contributions are the ones that:

- install cleanly on a real Betterness account
- make the starter easier to trust or extend
- add reusable operator depth for other OpenClaw builders
- include a clear smoke test and limitation section

The best submissions should be featured publicly and can be supported with lab credits when they materially improve the mission-control builder path.

## Best first contribution shapes

- a new specialist overlay
- a stronger recurring review prompt
- a new mission-control panel
- a new use-case adaptation with exact install notes

## Suggested submission package

- one markdown file for the asset itself
- one short README section explaining where it fits
- one smoke test using real Betterness tools
- one screenshot or workspace note if the asset is visual

## Submission checklist

Before you call a contribution ready:

1. install it into the reference mission control
2. verify the base Betterness smoke test still passes
3. verify the new asset solves one clear problem
4. document one limitation or guardrail
5. make sure another builder could reuse it without needing private context

## Community story

The goal is not promotion for its own sake.
The goal is to help builders install a working private health mission control faster, then publish improvements that the next builder can trust.
