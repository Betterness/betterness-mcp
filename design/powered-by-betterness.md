# BetterClaw OS Design Reference — Powered by Betterness

## Purpose

This file defines the exact placement and usage rules for Betterness attribution across BetterClaw OS workspaces.

## Principle

Betterness branding should feel confident, premium, and infrastructural. It should never feel like an ad overlay.

## Level 1 — Workspace Shell Footer

### Spec

Persistent footer line on the home view:

`Powered by Betterness · betterness.ai`

### Rules

- use muted text with strong legibility
- place the Betterness wordmark or logo-mark to the left
- keep spacing generous
- this is the default, always-on brand mark

### BetterClaw OS Usage

Used in every package shell.

## Level 2 — Module Attribution Chip

### Spec

Small chip at the bottom of a module card:

- `via Betterness Graph · updated 2h ago`
- `via Betterness MCP · 12 tools active`

### Rules

- use muted text
- optionally use a 2px left prismatic accent
- keep chips in footers, not headers

### BetterClaw OS Usage

Used when a module is materially powered by Betterness data or intelligence.

## Level 3 — Onboarding Connection Moment

### Spec

One prominent connection confirmation surface:

- Betterness logo or wordmark
- one horizontal prismatic rule
- `Connected`
- short status line summarizing what is now available
- one CTA: open the workspace

### Rules

- use the largest Betterness branding only here
- keep the composition centered and spacious
- this is the emotional “you are now inside the system” moment

### BetterClaw OS Usage

Used when a user first connects Betterness to OpenClaw.

## Level 4 — Canvas / Review Card Mark

### Spec

For generated canvases or review cards:

- small Betterness logo-mark in a corner
- 1px prismatic bottom border
- optional small caps `Betterness` source line

### Rules

- keep the mark small
- do not compete with the card’s main content
- apply only to major generated canvases and reviews

### BetterClaw OS Usage

Used for daily briefings, biomarker reviews, weekly summaries, and flagship canvases.

## What Not to Do

- do not place `Powered by Betterness` in headers or navigation
- do not add large logos to every module
- do not use full gradient backgrounds as the main branding gesture
- do not make the workspace feel sponsored or white-labeled in a cheap way
- do not use attribution more loudly than the package identity itself

## BetterClaw OS Package Usage

- **Recovery**: footer attribution plus occasional module chip
- **Marathon**: footer attribution plus race-week canvas marks
- **Biohacker Lab**: footer attribution plus biomarker review chips
- **Road Cycling**: footer attribution plus route or review card marks
- **Barry's / Studio**: footer attribution plus contextual listing attribution
